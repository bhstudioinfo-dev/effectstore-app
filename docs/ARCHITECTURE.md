# Architecture

## Folder Structure
- `backend/`: Express API, Mongo models, OBS/TikTok services, uploads, encrypted effect files.
- `backend/models/`: Mongoose schemas for users, effects, payments, gifts, menus, banners, settings, licenses.
- `backend/routes/`: REST routes mounted by `backend/server.js`.
- `backend/services/`: singleton services for TikTok, OBS, and the effect queue.
- `backend/utils/`: media encryption/streaming helpers.
- `desktop/`: Electron shell, local overlay server, renderer pages.
- `desktop/renderer/`: main app HTML, standalone admin/mapping/banner/overlay pages, CSS, client JS.
- `admin/`: older standalone admin page that appears out of sync with current `/api` route prefixes.
- `effects/`: loose effect media assets in repo root.
- `docs/`: project memory and human/AI documentation.

## Frontend/Backend Flow
1. Electron loads `desktop/renderer/index.html`.
2. `desktop/renderer/js/home.js` instantiates `EffectStoreApp`.
3. The renderer calls `http://127.0.0.1:9000/api/*` for auth, effects, payments, admin data, TikTok mappings, OBS, settings, and menus.
4. Backend routes read/write MongoDB through Mongoose models.
5. TikTok live events enter through `backend/services/tiktokService.js`.
6. Gift events are matched against `GiftMapping`; mapped effects enter `backend/services/effectQueue.js`.
7. The queue triggers OBS through `backend/services/obsService.js`.
8. OBS Browser Sources load `GET /api/obs/effect/:id`, which references `GET /api/stream/effect/:effectId`.

## State Management
- Frontend state is plain JavaScript in `EffectStoreApp` (`desktop/renderer/js/home.js`): current user, token, cart, current view, effects, owned effects, TikTok mappings, and TTS queue.
- Auth token and device id are stored in `localStorage`.
- Backend REST state is mostly persisted in MongoDB.
- Backend live state is in singleton services:
  - `tiktokService`: current room, live stats, reconnect timer.
  - `obsService`: connection state, reconnect timer, last OBS config.
  - `effectQueue`: in-memory sequential trigger queue.

## API Architecture
- Base URL: `http://localhost:9000/api`.
- Static mounts:
  - `/uploads`: `backend/uploads`.
  - `/assets`: `backend/assets`.
  - `/assets/gift-icons`: gift icon static alias.
- Most endpoints return `{ success: boolean, ... }`.
- Auth uses `Authorization: Bearer <jwt>` and middleware in `backend/middleware/auth.js`.
- Admin routes require `authMiddleware` plus `adminMiddleware`.
- File upload routes use multipart form data through Multer.

## Auth Flow
1. Register/login posts credentials to `/api/auth/register` or `/api/auth/login`.
2. Passwords are hashed/verified with `bcryptjs`.
3. Login may auto-create `admin@effectstore.vn` if absent.
4. Non-admin login enforces subscription-based active device count when a `machineId` is provided.
5. JWT includes `userId`, `isAdmin`, and sometimes `machineId`, expires in 7 days.
6. `/api/auth/me` validates token, downgrades expired subscriptions to `free`, and returns user metadata.

## Database Structure
MongoDB collections are generated by Mongoose from:
- `User`, `Effect`, `Payment`, `EffectRequest`, `GiftMapping`, `GiftLog`, `GiftConfig`, `OBSSettings`, `Banner`, `License`.

## Important Dependencies
- Backend: `express`, `mongoose`, `jsonwebtoken`, `bcryptjs`, `multer`, `ws`, `obs-websocket-js`, `tiktok-live-connector`, `qrcode`, `fluent-ffmpeg`, `nodemailer`, `axios`.
- Desktop: `electron`, `electron-builder`, `express`, `ws`, `auto-launch`.
- Renderer external CDNs: CryptoJS and Font Awesome in `desktop/renderer/index.html`; Google Fonts in some standalone pages.

## Design Patterns
- Singleton services for TikTok, OBS, and effect queue.
- Queue pattern for sequential OBS effect playback.
- Local-first architecture: backend and desktop communicate over localhost.
- Static renderer SPA style: view switching via DOM and `EffectStoreApp`, not a frontend framework.
- File-backed media pipeline: uploads/temp -> previews/thumbs/encrypted -> stream endpoint.

## Risky Coupling
- Renderer hardcodes `127.0.0.1:9000`/`localhost:9000` in many places.
- Some standalone pages call endpoints that are missing or use old auth headers.
- Backend stores absolute/relative local filesystem paths in Mongo documents.
- Secrets and defaults are hardcoded for development and must be overridden in real deployments.
